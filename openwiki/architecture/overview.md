# Architecture: Overview

Mimir is not an application; it is a **document-driven agent suite**. Each skill is a directory (`skills/wiki-*/`) containing a `SKILL.md` (instructions the Hermes agent reads) plus deterministic Python CLI scripts. The agent decides *when* and *with what content* to act; the scripts guarantee *how* files land on disk. See [Domain: Conventions](../domain/conventions-and-method.md) for the invariants that bind all of them.

## The vault layout (runtime, not in this repo)

All state lives under a user-chosen `work_root` (an Obsidian vault or a dedicated folder), defined by the user's `wiki.config.json`:

| Path | Role | Mutability |
|---|---|---|
| `_inbox/` | dropzone for new sources | transient — extract *moves* files out after success |
| `raw/pdfs/`, `raw/epubs/`, `raw/web/`, `raw/notes/` | immutable raw material + `_assets/` + `.toc.json` + `_status.md` | append-only; only `_status.md` mutates |
| `wiki/<subject>/` | notion articles + `/_assets/` + `_INDEX.md` | rewritten by ingest/index |
| `reading-grids/` | per-book reading grids + research reports | regenerated by grid/index |
| `.wiki/ingest-ledger.json` | machine-local ledger: source SHA → compiled articles | **excluded from sync** |
| `.mimir/vault.json` | vault schema-version marker (synced); `.mimir/snapshots/` excluded | bumped by [migration engine](../architecture/shared-core.md) |

## Configuration: "configure once, call without `--config`"

`config_loader.resolve_config_path()` picks the first *existing* `wiki.config.json` from:

1. explicit `--config` argument
2. `$MIMIR_CONFIG` env var
3. the Hermes profile dir (`~/.hermes/profiles/mimir/wiki.config.json`) — auto-discovered since v0.3.3
4. `~/.config/mimir/wiki.config.json` (XDG)
5. `./wiki.config.json` (cwd — least trusted, cron has no guaranteed cwd)

It validates against `skills/_shared-references/schema/wiki.config.schema.json` (jsonschema if installed, manual fallback otherwise) and exposes a frozen `Config` dataclass with absolute derived paths (`INBOX`, `RAW`, `WIKI`, `READING_GRIDS`, `LEDGER`, `VAULT_META`, `SNAPSHOTS_DIR`) and the chosen sync `backend` (default `rclone`). Template: `wiki.config.example.json`. Mode A (full vault with `.obsidian/`) vs Mode B (dedicated dir) is inferred from the path and only informs sync scope. Details: [Runbook](../operations/runbook.md).

## Skills as scripts: the coupling graph

Every entrypoint starts with the same stanza — prepend `skills/_shared-references/scripts` to `sys.path` and `import bootstrap` — so all shared symbols fail at import time, not mid-run. Beyond the shared core ([Shared Core Library](../architecture/shared-core.md)), there is deliberate **cross-skill coupling**:

- `wiki-batch-produce/scripts/batch_produce.py` imports `wiki_ingest` (to run `finalize` per source) and `wiki_index`/`link_audit` (best-effort audit at the end) from sibling skill dirs.
- `wiki-research/scripts/wiki_research.py` imports `wiki_extract` to clip URLs — research reports are therefore built from the same `raw/web/` clips as [Ingestion: wiki-extract](../pipeline/ingestion-skills.md).
- `wiki_sync.py` shells out to `wiki-index`'s audit when `sync.presync_gate=true`.
- `wiki-reading-grid` and the v2→v3/v3→v4 migration paliers import, respectively, `grid_builder` and `extractors.web` across skill boundaries (wired in `skills/_shared-references/tests/conftest.py`).

**Watch out:** these sibling imports assume the whole `skills/` tree is installed together (which is exactly what `hermes profile install` does — it copies the entire repo into the profile dir; `distribution.yaml` has no `files:` key).

## Deterministic vs semantic: the design line

| Deterministic (scripts) | Semantic (the agent, per SKILL.md) |
|---|---|
| extraction, SHA/URL dedup, slugs, atomic confined writes | notion decomposition of a source |
| ledger/status bookkeeping | Karpathy rephrasing of article bodies |
| grid skeleton (toc order × ledger × `#chK` anchors) | one-line editorial blurbs in `<!-- blurb:start -->` zones |
| index regeneration, link audit passes | `--semantic-map` broken-link proposals, INDEX subject descriptions |
| clip/scaffold/update for research | source selection + synthesis report writing |

`wiki-batch-produce` is the pure-determinist extreme ("no LLM call": 1 URL = 1 notion, content lifted from the source); `wiki-research` is the semantic extreme (script only clips and scaffolds). This split exists so the pipeline is testable hermetically and rerunnable idempotently while quality judgment stays with the model.

## Sync: every skill is a sync client

All writing skills end with a sync step (`pull` before reading `raw/`, `push`+`validate` after writes, skippable via `--skip-sync`), routed through the pluggable backend in the shared core — rclone (hardened kDrive WebDAV bisync), git, Obsidian Remotely Save, or `auto` (probe Obsidian, fall back to rclone mid-run). A mutex lock lives **outside** the synced zone (`~/.cache/mimir/wiki-sync.lock`). Backends and failure semantics: [Pipeline: wiki-sync](../pipeline/knowledge-skills.md) and [Runbook](../operations/runbook.md).

## Vault schema migrations ("paliers")

The vault's structure carries a schema version in `.mimir/vault.json` (`EXPECTED_SCHEMA = 4` in `config_loader.py`). Three registered paliers migrate old vaults: v1→v2 per-source PDF assets, v2→v3 web extraction fidelity (refetch to rebuild the `.html`+`.md`+assets triplet), v3→v4 reading-grid guide format. `wiki-init status` reports pending paliers. Engine/snapshot/lazy details: [Shared Core Library](../architecture/shared-core.md).

## Key source references

- `skills/_shared-references/scripts/config_loader.py` — config resolution, `Config`, `EXPECTED_SCHEMA`
- `skills/_shared-references/scripts/bootstrap.py` — unified import stanza, `MIMIR_SHARED` override
- `skills/_shared-references/scripts/guard.py` — `work_root` confinement (`assert_within`, `safe_path`)
- `distribution.yaml` — Hermes distribution manifest; `config.yaml` — profile config notes (French)
- `README.md`, `SOUL.md` — product vision and persona/convention memory

## Changing this area

- New skill: copy the `skills/wiki-*/` shape (SKILL.md + `scripts/` + `tests/conftest.py` injecting shared paths), start scripts with the bootstrap stanza, and register it in `skills.sh.json`, `README.md`, `SOUL.md`, `CHANGELOG.md` counts (past releases mechanically updated these).
- New vault-layout invariant: bump `EXPECTED_SCHEMA` only with a registered palier in `skills/_shared-references/scripts/migration/paliers/`, otherwise old vaults report pending migrations forever.
